# data/network_500kv

Processed files from the 500 kV network construction pipeline.
Generated by running the scripts in `scripts/network_500kv/` in order.

## Detail

### `buses_500kv_raw.csv`
**Source:** PSS/E `ver2526pid.raw` (CAMMESA)

500 kV buses from the PSS/E base case with their electrical parameters.
One record per bus. Excludes buses with IDE=4 (isolated) and international buses.

| Field | Description |
|-------|-------------|
| `bus_id` | Numeric ID in PSS/E |
| `bus_name` | Bus name |
| `baskv_kv` | Base voltage (kV) |
| `ide` | Type: 1=PQ, 2=PV, 3=slack |
| `ide_desc` | Bus type description |
| `area` | CAMMESA electrical area |
| `vm_pu` | Base case voltage magnitude (pu) |
| `va_deg` | Base case voltage angle (degrees) |

---

### `lines_500kv_raw.csv`
**Source:** PSS/E `ver2526pid.raw` (CAMMESA)

500 kV lines and series compensators with impedances and ratings from the PSS/E base case.

| Field | Description |
|-------|-------------|
| `line_key` | Human-readable identifier: `BUS_I-BUS_J-CKT` |
| `bus_i` / `bus_j` | Terminal bus IDs |
| `ckt` | Circuit number (1, 2, 3...) |
| `r_pu` / `x_pu` / `b_pu` | Impedances in pu (Sbase=100 MVA) |
| `ratea_mva` | Thermal rating in MVA (NaN if not defined) |
| `len_km` | Length in km |
| `element_type` | `line` or `series_compensator` |
| `in_service` | True if the branch is in service |

### `trafos_500kv_raw.csv`
**Source:** PSS/E `ver2526pid.raw` (CAMMESA)

Transformers with at least one 500 kV winding. 3-winding transformers are decomposed
into two 2-winding transformers using the 500 kV winding as the common reference.

| Field | Description |
|-------|-------------|
| `trafo_key` | Human-readable identifier: `BUS_I-BUS_J-CKT` |
| `bus_i` | 500 kV bus (always the high-voltage side) |
| `bus_j` | Secondary bus (low-voltage side) |
| `ckt` | Circuit number |
| `origin` | `2W` (original) or `3W_decomp` (decomposed from 3-winding) |
| `r_pu` / `x_pu` | Impedances in pu (Sbase=100 MVA) |
| `sbase_mva` | Transformer base power in MVA |
| `in_service` | True if the transformer is in service |

### `marginal_costs_2024.csv`
**Source:** `18b_build_marginal_costs_2024.py`

Fixed annual marginal cost per generator unit, plus per-unit efficiency and
heat rate from CAMMESA. Direct input for the operational optimization
(script 19), the simplified network builder (script 20A) and the future-year
scenario builder (script 21).

| Field | Description |
|-------|-------------|
| `gen_key` | Unique PSS/E key |
| `bus_name_origen` | Origin bus name |
| `geosadi_name` | Power plant name in GeoSADI |
| `nemo` | CAMMESA code |
| `bus_conexion500kv` / `bus_conexion500kv_name` | Model bus the unit connects to |
| `carrier` | PyPSA technology type |
| `p_nom` | Installed capacity (MW) |
| `lat` / `lon` | Geographic coordinates (WGS84) |
| `marginal_cost` | Fixed annual marginal cost from CVP files (USD/MWh) |
| `efficiency` | Net electrical efficiency from CAMMESA `efficencies.xlsx` (decimal). Empty for units without a match. |
| `heat_rate_kcal_per_kwh` | Net heat rate (`C.E.NETO`) from the same file (kcal of fuel per kWh of electricity). Empty for units without a match. |

**Source:** `20B_network_clustering.py`
**Local path:** `data/network_500kv/clusters/cluster_k{N}.nc` (not versioned in git)

Spatially clustered version of `network_500kv_simplified.nc` reduced to K

Per-machine efficiency table from CAMMESA. Single sheet `CONS ESP NETO`
with one row per (generator, fuel) combination — many machines have multiple

| Field | Description |
|-------|-------------|
| `GENERADOR` | CAMMESA machine code (e.g. `ACAJTG02`, `ACAJCC01`). |
| `COMBUSTIBLE` | Fuel code: `GN` / `FO` / `GO` / `CM` / `U2` / `UA` / `UE`. |
| `C.E.NETO (kcal/kWh)` | Net specific consumption (kcal of fuel per kWh of electricity). |
| `Eficiencia (%)` | Net electrical efficiency (decimal, despite the column header). |

Read by `18b_build_marginal_costs_2024.py`. The fuel hierarchy applied is
GN > FO > GO. CC records (`XXXXCC??`) are also used to populate efficiency
for the TG and TV units of the same plant via the inheritance rule
documented in the script's README entry.

### `fuel_properties.yaml` *(external to GitHub)*
**Source:** Manual
**Local path:** `external_data_dir/fuels/fuel_properties.yaml`

Universal physical constants per fuel code. One block per fuel (`GN`, `FO`,
`GO`, `CM`):

```yaml
GN:
  name: "Gas Natural"
  heating_value: 8400.0          # kcal per physical_unit
  physical_unit: "m3"
  report_unit: "dam3"
  physical_to_report_factor: 0.001
  co2_emission_factor: 1.95      # tCO2 per report_unit
```

Heating values follow CAMMESA convention. CO2 emission factors come from
the Argentine Tercer BUR (IPCC defaults using BEN net calorific values).
Read by `21_build_scenario.py` (for marginal cost computation) and
`22_run_scenario.py` (for fuel consumption and emissions accounting).

### `carrier_defaults.yaml` *(external to GitHub)*
**Source:** Manual
**Local path:** `external_data_dir/fuels/carrier_defaults.yaml`

Per-carrier default fuel code and fallback efficiency, used by
`21_build_scenario.py` for thermal generators that are missing data in
`efficencies.xlsx`. Two blocks:

- `default_fuel_by_carrier`: maps `ccgt`/`ocgt` → `GN`, `diesel` → `GO`,
  `steam` → `FO`, `nuclear` → null.
- `fallback_efficiency_by_carrier`: ATB-based efficiency per carrier
  (CCGT 0.585, OCGT 0.415, diesel 0.350, steam 0.350, nuclear 0.330).

Modeling decisions (which fuel to assume, which efficiency to fall back to)
live here so they can be reviewed and updated without touching code.

### `costs_2035_US.csv` *(external to GitHub)*
**Source:** External (NREL Annual Technology Baseline, US Market+Moderate scenario)
**Local path:** `external_data_dir/Technology_data/costs_2035_US.csv`

Technology cost assumptions for 2035 used by `21_build_scenario.py` when
adding expandable generators. Long format (one row per technology-parameter
pair). Parameters used: `investment` (USD/MW), `FOM` (% of capex per year),
`VOM` (USD/MWh), `efficiency` (decimal), `lifetime` (years), `discount rate`
(WACC).

For technologies not present in the ATB file (typically newer tags), code
falls back to hardcoded defaults documented in the script.
